# 三件套编写规范（card / contract / mapping）v0.1 草稿

> 定位：operator/需求侧的执行 SOP——给"要写新任务三件套的人或 agent"。平台级知识，最终归宿是平台仓 operator 侧 skill（T5 批次提炼入库）；本文档是需求侧权威草稿。
> 铁律的强制点在平台代码（`aidev/specs.py`、`aidev/lifecycle.py` 的 freeze/refreeze 校验），本规范解释铁律与撰写方法。
> 教材：状态仓 `specs/` 下全部冻结件（t0–t6 七套），写新三件套前先读最接近的一套。

## 0. 三件套是什么、谁先谁后

| 文件 | 回答的问题 | 谁来写 |
|---|---|---|
| `acceptance-card.json` | 什么叫完成（AC 条目，含 must / must-not / safety-veto /【人工】） | 需求方 |
| `contract.json` | 怎么证明（机测用例清单 + 运行环境契约） | 需求方 |
| `mapping.json` | AC 与用例怎么对应（一案一行） | 需求方 |

工作流：**先写 card（完成定义）→ 再写 contract（证明手段）→ 最后 mapping（对账）→ freeze 冻结**。冻结后任务才 Ready。改规格走 refreeze（reason 必填，版本 +1）。

> 术语："钉扎"（pin）指 freeze 那一刻把三件套的内容哈希写进任务账本。之后 agent claim/submit 时，平台核对它工作区里的三件套副本哈希与账本是否一致——不一致就是 `claim.spec_hash_mismatch`（签的是 A 版、做的是 B 版）。人话叫**冻结版本核对**。三处用词：面向人的文档/页面说"冻结版本"；agent 工具输出沿用"钉扎"；机器字段（spec_pin）不动。

## 1. 验收卡（acceptance-card.json）撰写

- **card 是给人读的**：写"完成定义"的人话——做什么、做到什么程度算完、哪些要人眼看。术语（钉扎/幂等/字面环境）属于 contract 和 verify_notes 的语言，正文能不用就不用。
- `criteria[]` 每条：`criterion_id`（AC-NN）、`strength`（must / must-not / safety-veto）、`text`。
- 一条 AC 只陈述一个可判定命题；must-not 写"不得回归的既有行为"；safety-veto 用于"失败必须当场喊停"的红线（机测 + 人工复跑双轨，见 mapping）。
- 【人工】条目末尾标注，机测覆盖不到的（页面观感、审计人审、全量回归执行）归人工，由验证人 `--manual-results` 记录。
- **主观需求同样走三件套**（原型/规范/观感类）：主观 ≠ 无约束——①先穷举机测代理（页面类用呈现断言：导航集合一致、CSS tokens 类名落地、链接可达），能机器兜底的绝不留给口味；②残余的真主观进【人工】，条目写清"谁确认、按什么、留什么证据"（如"owner 走查原型主流程并签署"），确认即验收，验证人 `--manual-results` 落证据（带 sha256）；③冻结对本类需求价值最大——验收照钉扎版本执行，防"验收时标准已漂移"；mapping 纪律不变：机测覆盖 ∪ 人工覆盖 = card 全集。角色分离天然成立：实现者为 operator/agent 侧，confirm 者为 owner（confirm ≠ 实现者的既有规则不破）。
- `verify_notes` **必须写清验收字面环境**：服务绑定变量（STATE 克隆 / PLATFORM 仓 / BASE_URL 自引用）、端口空闲要求（8000）、编排副作用声明（会真实建号/建任务/写状态仓 → 可弃置克隆）、编排账号清理责任。字面环境是完成定义的一部分。

## 2. 契约（contract.json）撰写

- `environment`：
  - `runner`: "python"；`allowed_env` 白名单——用例子进程**只能**看到这些变量。服务端执行场景三件套：`SIGNET_BASE_URL`（自引用）、`SIGNET_PLATFORM_REPO`（定位被测代码）、`SIGNET_STATE_REPO`（编排基准仓）。系统变量（PATH/SYSTEMROOT/USERPROFILE…）按需加。
  - 不要假设 PATH 之外的任何环境（试点教训 P2）。
- `cases[]` 一案一行，每案：`case_id`、`command`（argv 数组，首元素是可执行名）、`operation_set: null`（本迭代全 null，非 null 须 freeze 时传 `--operation-source`）。
- 用例脚本规范：
  - **布尔断言必须显式 `bool()` 包裹**（`and` 链陷阱，试点教训 P1）；
  - 断言失败输出可诊断信息（哪个端点、哪个字段、期望/实际）；
  - 编排类用例（要真实写状态仓的：建号/建任务/freeze/claim/submit）必须声明在 verify_notes 且打可弃置克隆；
  - 输出统一 JSON 结算（如 `{"ok": true, ...}`），机器窗口能抓取；
  - 资产文件（fixture）随 freeze 上传，`asset_manifest` 记录相对路径，签署时 sha256 核对。
- `setup_command` 一般为 null。

## 3. 映射（mapping.json）撰写

- `rows[]` **一案一行**：`criterion_id` + `manual: true/false` + `case_ids[]`（可空）。
- 一案不可跨行（一个 case 只出现在一行）；一案可多案（AC-11 = sigt-inspect + no-secret-leak 两案）。
- safety-veto 行：`manual: false`（机测跑）+ 验证时另交 `manual_rerun`（复跑命令+证据）。
- 每个 criterion 恰好被覆盖一次：机测覆盖 ∪ 人工覆盖 = card 全集，多覆盖少覆盖都被 `verify.incomplete_results` 拒。

## 4. 冻结与签署

```
python aidev-operator.py freeze --repo <状态仓> --task-id <全id> --workspace <工作区> \
  --acceptance-card card.json --contract contract.json --mapping mapping.json \
  --h1-actor <签H1人> --h2-actor <签H2人> \
  [--operation-source operations.json] [--push]
# 资产文件：按 CLI 提示随令上传（asset_manifest 自动构建）
# H1=内容确认（写得对），H2=一致性确认（三件套装配互洽），可同人双签，须显式指定
```

- freeze 前自查三件套互一致：card 的 criterion_id 全集 == mapping rows 全集；contract 的 case_id 全集 == mapping case_ids 并集。
- 用例必须**先于 freeze 在字面环境全绿**（自己跑一遍 `command`），冻结的才是完成定义。
- 哈希以 pin 形式写入任务 spec_pin，claim/submit 时平台核对冻结件副本（工作区 contract/）。
- **改冻结资产必须同步改清单**：修改/替换 contract 资产文件（fixture）后，必须同步更新 contract.json `assets` 清单里该文件的 sha256——freeze/refreeze 会重算每个资产哈希与清单核对，不一致即 `c3.asset_hash_mismatch` 拒收（T5 v3 refreeze 实战教训：首跑因漏改清单被拒，补清单后通过）。
- 变更用例或资产后，以其钉扎组合跑一遍最小冒烟再 freeze/refreeze——用例自身绿才允许冻结（流入冻结件的用例缺陷在任何实现下都不可通过，代价是一次 block/refreeze 往返）。

## 5. 常见被拒原因（freeze/verify 报错词典）

| 报错 | 含义 |
|---|---|
| `c2.*` / `c1.*` | 契约/卡 schema 不符（一案一行、safety-veto 机验等） |
| `verify.incomplete_results` | mapping 覆盖与 card 不一致 |
| `verify.manual_results_required` | 有人工行但 `--manual-results` 缺失或 verifier 不匹配 |
| `verify.failed_criterion` | 用例红了，details 列 criterion |
| `claim.spec_hash_mismatch` | 工作区 contract/ 副本被改过 |

## 6. 演进

- 本规范随平台 schema 演进；铁律变更必须先改平台代码与本文档，再 freeze 新任务。
- 模板化/脚手架（生成骨架人填内容）是债务候选，见设计稿 §15。

# 页面呈现规范 v0.1 草稿（线框原型级）

> 定位：T3/T4 暴露的页面规格盲区的补票。先有本文（线框即原型），用户 review 方向后：
> ① 在真实服务上做一页活样张（看板页）确认品味 → ② 修订本规范 → ③ 按三件套流程派发"页面呈现统一化"任务。
> 技术约束：服务端渲染、无 JS（v1）、无外部资产（内联 CSS）。

## 0. 设计原则

1. **工具界面**：信息密度与扫读效率优先，不做营销式留白；
2. **页面即文档**：每个页面同时是"该状态的说明书"（交接卡/派活卡已经是这个思路）；
3. **无 JS v1**：所有交互都是链接与表单提交，退化为纯 HTTP 后每个页面仍可用 curl 复核（机测友好的延伸）；
4. **中文排版**：全角标点、中英文间留白、id/路径一律 `<code>` 等宽。

### 3.3 任务看板 `/tasks`

### 3.5 需求列表 `/requirements`

### 3.7 新建任务 `/tasks/new`
```text

[创建任务] → 303 跳详情（现状保留）
```

## 4. 导航一致性规则

1. 面包屑固定格式：`概况 / <当前页> / <实体id短码>`，纯文本+链接，不用图形符号；
2. 每页只允许一个"主操作"（右上：新建任务/去验收），其余为次级链接；
3. id 显示统一：全文 mono，列表中截断为 12 字符+title 悬浮全文。

## 5. 写成验收标准的建议（三件套用法）

- 功能断言保留现状（字段/重定向/状态码），新增**呈现断言**：导航条存在且 7 页一致（逐页断言导航链接集合）、CSS tokens 落地（检查关键类名存在，如 `.task-card`/`.topbar`）、交接卡/派活卡左边框卡片类名；
- 【人工】条目：每页扫读观感走查 + 活样张对照；
- 用例形态：页面 HTML 断言（现有 case-dispatch-card 模式的扩展）+ 全局样式守卫。
